# 安全与合规

## 边界

- **只读**：CLI 只调用学校前端本来就会调用的查询接口，查的是当前登录用户有权看到的数据。
- **不代登录**：用户在可见浏览器里本人登录；CLI 不输入、不保存、不传输密码或短信验证码。
- **不绕过**：不绕过验证码（例如图书馆系统的滑块验证）、VPN、校园网络限制、限流和权限控制。
- **低频**：每条命令只发出必要的请求。分页上限是固定的（成绩、方案最多 20 页，通知搜索最多 30 页），不做轮询。

## 数据处理

- 输出前剥离接口里夹带的他人敏感信息，例如教师身份证号、电话、出生日期（`stripSensitive`）。
- 学生本人的成绩、学号等只在本机命令输出里出现，不会发往任何第三方服务。
- 登录态保存在 `~/.njau-cli`，文件权限 600。

## 仓库卫生

- 不提交 cookie、profile、HAR、trace、截图。
- 不提交任何从学校系统抓取的数据，包括“脱敏”后的接口返回。测试 fixture 一律用合成数据生成（`tests/fixtures/szjw-synthetic.js`）。
- 调试抓取的数据放在 `scratch/`（已 gitignore）。

## 写操作（预留）

如果将来要加写操作（例如预约），必须同时满足：

1. 支持 `--dry-run` 预览；
2. 真正执行需要 `--confirm`，并且由用户明确同意；
3. 执行后重新查询，验证结果；
4. 不通过 MCP 暴露，除非客户端能逐次征求用户确认。

选课、退课不在计划内：抢课脚本会给教务系统带来压力，账号也有被风控的风险。
